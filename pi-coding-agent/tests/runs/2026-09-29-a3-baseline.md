## Transcript (the agent's final report, verbatim)

**Answer:** Pi 0.99.1 has no built-in spending limit. I searched its shipped docs, README, CHANGELOG and examples and found no setting, flag or env var for a cost cap. The only "budget" settings are unrelated: `thinkingBudgets`, `codemode.inlineBudget` and compaction budgets. What Pi does give you is cost display and accounting:
- The footer shows accumulated usage and cost.
- `/session` shows token usage and cost.
- Usage entries in the session file carry `usage.cost.total` (docs/session-format.md).

To stop a session at $5 you would write an extension. This is the approach the docs point to. I did not write or run one, so this is unverified and only a sketch:
1. Load a TypeScript extension, either with `pi -e ./budget.ts` or from the extensions directory.
2. In a `turn_end` or `message_end` handler, sum `usage.cost.total` over the session's assistant messages and usage entries. `ctx.sessionManager.getBranch()` gives you the entries, and docs/session-format.md describes the `usage.cost` shape.
3. When the sum reaches 5, call `ctx.shutdown()`. It requests an orderly exit and is deferred until the agent is idle.
4. Alternatively, `tool_call` handlers can block execution.
5. The `turn_end` handler runs after each turn, so the cap can overshoot by up to one turn's cost. It cannot stop a single very expensive request mid-flight.

For cost accounting, extension tools that make nested model calls should include their `usage` in their result so session totals stay accurate (docs/extensions.md). The cheapest starting points are `examples/extensions/shutdown-command.ts` (shows `ctx.shutdown()`) and `examples/extensions/custom-footer.ts` (shows reading session state).
