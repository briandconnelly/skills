## Final answer

I set up a Pi virtual model, `router/auto`, as an extension. Select it once with `--model router/auto` or `/model` and Pi routes each request itself. The extension is `/Users/bdc/projects/skills/.eval-tmp/pi-scenarios/b3-baseline/pi-agent/extensions/size-router.ts`, which Pi auto-loads from the agent dir.

I have not tested it end to end. This sandbox has no llama.cpp server on 127.0.0.1:8080 and no Anthropic credentials, so no live request ran. What I verified:
- Pi loads the extension and lists `router/auto`.
- The routing function picks the right model in a mock run, described under "Routing rules" below.

To use it:
1. Run `/login anthropic` and `/login llama.cpp`. The llama.cpp router must be running and have a model loaded (`/llama`).
2. Start Pi with `pi --model router/auto`.

Routing rules:
- **Local:** a short question goes to the first available `llama.cpp` model. "Short" means one line, at most 200 characters, ending in `?`, with no code fence. Thinking is set to off.
- **Claude:** everything else goes to `anthropic/claude-sonnet-5-5`.
- **No local model available:** the request goes to Claude.
- **Follow-ups:** tool follow-ups and continuations stay on the model that handled the turn, which keeps the prompt cache.
- **Failed local request:** the retry goes to Claude.

The mock run gave these results:
- Short question: local.
- Long task: Claude.
- Multi-line question: Claude.
- Short question with no local model: Claude.
- Continuation after a local answer: local.
- Retry after a local failure: Claude.

Settings you can change with environment variables:
- `ROUTER_SHORT_MAX`: the length cutoff (default 200 characters).
- `ROUTER_LOCAL_MODEL`: a specific llama.cpp model ID.
- `ROUTER_CLAUDE_MODEL`: the Claude model ID.

Two things are guesses. The `?` plus length rule is my own heuristic for "short question", since you didn't define one. The docs also describe a classifier-based approach (`jev-router.ts`), which I did not use.
